What is Titan M2?

🔐 Hardware Security Chip

A separate physical chip on your Pixel that stores cryptographic keys in a way that cannot be extracted, even by root access.

🛡️ StrongBox Security

Keys are generated and stored inside the chip. Private keys never leave the hardware. Only signatures come out.

This is the trust anchor of the entire system.

Step 1: Key Generation

// Generate EC key pair in Titan M2 KeyGenParameterSpec.Builder(KEY_ALIAS, PURPOSE_SIGN) .setIsStrongBoxBacked(true) // Use Titan M2 .setAttestationChallenge(random) // Include challenge .build()

Result: A private key in Titan M2 + certificate chain proving it's in hardware

Private Key (Never Leaves Titan M2) Public Key (Shareable) 5 Certificate Chain

Certificate Chain

The attestation certificate chain proves hardware origin:

📜 Leaf Certificate: Your app's key (CN=Android Keystore Key)
↓ signed by ↓
🏭 StrongBox Certificate: Titan M2 hardware (O=StrongBox)
↓ signed by ↓
🔐 Google Intermediate: Google Hardware Attestation
↓ signed by ↓
⚡ Google Root CA: Publicly trusted root

Each certificate is cryptographically signed by the one above it.

Step 2: Recording Audio

🎤 Record audio from microphone
↓
✂️ Split into 5-second chunks
↓
🔢 Hash each chunk (SHA-256)
↓
📦 Create payload: timestamp + index + hash + recording_id
↓
✍️ Sign with Titan M2 key (ECDSA)

What Gets Signed?

// For each 5-second audio chunk: payload = { timestamp: 1726086005000 (when recorded) chunk_index: 0 (chunk number) audio_hash: 3a4b5c6d... (SHA-256 of audio) recording_id: uuid (unique session) } signature = ECDSA_sign(payload, titan_m2_key)

The signature cryptographically binds:

  • Audio content (via hash)
  • When it was recorded (timestamp)
  • Which device (via key in Titan M2)

Step 3: Verification

🔍 Certificate Chain

✅ Verify each cert is signed by next
✅ Check dates are valid
✅ Confirm StrongBox issuer
✅ Validate up to Google root CA

🎵 Audio Signatures

✅ Hash each audio chunk
✅ Reconstruct payload
✅ Verify ECDSA signature
✅ Check all chunks match

If verification succeeds → Cryptographic proof!

What Attestation Actually Proves

✅ DOES Prove

  • 🔐 Key is in Titan M2 hardware
  • 📱 Specific device identity
  • 📦 App package name
  • 🔒 Bootloader state
  • ✍️ Signature is authentic
  • 🔗 Data hasn't been modified

❌ Does NOT Prove

  • ⚠️ App logic is correct
  • ⚠️ Audio is real vs fake
  • ⚠️ Microphone was used
  • ⚠️ App wasn't compromised
  • ⚠️ Right code is running

The Trust Chain

Your trust depends on these layers:

1. Hardware: Titan M2 is trustworthy ✅
↓
2. OS: GrapheneOS maintains integrity ✅
↓
3. App Identity: Package name in attestation ⚠️
↓
4. App Logic: Code does what it claims ❌

Key insight: Attestation proves identity and authenticity, but NOT correctness of behavior.

Attack Scenarios

✅ Prevented

Tampering after recording:
Can't modify audio chunks without breaking signatures.

Key extraction:
Private key never leaves Titan M2.

Device impersonation:
Each device has unique attestation.

❌ NOT Prevented

Malicious app update:
Updated app could sign fake audio.

Synthetic audio:
App could sign TTS instead of mic.

Compromised build:
Modified APK could do anything.
